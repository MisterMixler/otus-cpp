# otus-cpp / lab8 — `SameFinder` (поиск дубликатов файлов)

Утилита для обнаружения файлов-дубликатов по содержимому с **бережным** обращением к дисковому I/O.

Используется Boost:
- `Boost.Program_options` — параметры командной строки
- `Boost.Filesystem` — обход директорий
- `Boost.CRC` / `boost::uuids::detail::md5` — хэширование блоков

## Сборка

```bash
sudo apt-get update
sudo apt-get install -y libboost-program-options-dev libboost-filesystem-dev
cmake -S . -B build
cmake --build build
```

## Использование

Все параметры задаются через CLI. Справка:

```bash
./build/SameFinder --help
```

Основные параметры (соответствуют заданию):
- **`--scan, -s`**: директории для сканирования (может быть несколько)
- **`--exclude, -e`**: директории для исключения (может быть несколько)
- **`--depth, -d`**: уровень сканирования (0 — только указанная директория без вложенных)
- **`--min-size, -m`**: минимальный размер файла (байты), по умолчанию 1
- **`--mask`**: маски имён файлов для сравнения (case-insensitive), например `*.txt *.cpp`
- **`--block-size, -b`**: размер блока чтения \(S\) (байты)
- **`--hash, -H`**: алгоритм хеширования блоков \(H\): `crc32` или `md5`

Пример:

```bash
./build/SameFinder \
  --scan . /var/log \
  --exclude ./build ./.git \
  --depth 5 \
  --min-size 2 \
  --mask "*.txt" "*.log" \
  --block-size 4096 \
  --hash crc32
```

## Формат вывода

На стандартный вывод печатаются **полные пути**. На одной строке один файл.
Идентичные файлы идут подряд одной группой, разные группы разделяются пустой строкой.

## Использованные паттерны/приёмы проектирования

- **Strategy**: выбор алгоритма хеширования блока через `samefinder::HashAlgorithm`
  (`crc32` / `md5`) без изменения алгоритма обхода/сравнения.
- **Lazy evaluation**: чтение и хеширование блоков выполняется только
  “по требованию” при реальном сравнении кандидатов; каждый блок файла читается с диска
  не более одного раза (кэш последовательности хешей в `FileReader`).
- **Facade**: библиотечный API `SameFinderLib` скрывает детали (обход, фильтрация,
  ленивое чтение, группировка) за функциями `collect_candidates()` / `find_duplicates()`.
- **Pipeline / Refinement**: кандидаты последовательно “сужаются” стадиями
  *размер → хеш блока 0 → хеш блока 1 → ...*, что минимизирует лишние чтения.
